Note Organizer

An offline notes app for Windows, with an Android companion on the way - rich notes with tables and checklists, notes that repeat, and a calendar that shows them. No account, no cloud, no network calls: everything stays on your own device, and a share code is the only thing that ever moves between them.

Live demo View on GitHub How it's tested Bug reports

What it does

Rich text (bold, italic, colours, headings, lists), tables you edit in place, a checklist under every note, notes that repeat on a schedule, a calendar that shows them, search/sort/group, a Trash you can restore from, full backups, and copy-paste share codes between copies of the app. Eight light/dark themes. An Android companion app is in progress, sharing the same eight themes and reading the same share codes and backups as the Windows app.

My role

Product decisions, every design and testing call, and three years of technical-support experience feeding directly into what the app protects against. Built in pair-programming with an AI coding agent (Claude Code): I decide what it does, test every change by hand on the packaged app, and approve it before it merges.

Quality

~5,000 automated checks across 9 GUI suites and 8 unit suites, run on both Windows and Linux. 1,455 mutants (fixes deliberately removed to prove a check actually fails without them) and 992 manual test cases, 604 of them passed by hand on the packaged app (the rest by scripts or still to do). Every colour pair in all eight themes is measured against WCAG AA; CI fails on any that isn't. The Android companion has its own suite: about 1,100 unit tests and roughly 679 checks walked by hand on an emulator.

Status

In active development, not yet a 1.0 release - the site, demo and source are all public now, for both apps. The Android companion (v0.15.2) is public too, but not yet on Google Play. Both live links are browser recreations of the interface; the real apps are a Windows program in Python/Tkinter and an Android app in Kotlin that a browser can't run - though a share code moves a note between the two demos just like it does between the real apps.

Why this exists

Everyone takes notes, whatever they do. I spent years in support, and I saw how much time is lost when notes are short or scattered.

I wanted a simple, dependable place for notes that works offline and keeps the data on the user's own machine - no account to lose access to, no server to go down, nothing phoned home. The interesting part wasn't the note-taking itself; it was building the parts people only notice when they fail: a delete you can always undo, an import that never silently overwrites what you already had, and a save that survives a slow machine, a mid-typing crash, or doing the same thing twice.

Highlights

  • A delete you can undo looks different from one you can't. Moving a note to the Trash is a quiet red; deleting it from the Trash for good is a dark red that asks first - and on anything irreversible, both Enter and Escape give the safe answer.
  • Meaning carried by shape, not just colour. Save is the one filled button, the open tab stands taller, the current search match is boxed - checked against colour-blindness simulations, not just assumed to be readable.
  • Nothing you type is lost to a wrong field. A date that can't be read, an import that overlaps what's already there, a note left half-written when you switch away - the app keeps what you wrote and asks, instead of guessing or discarding it.
  • Fixes are proved, not just believed. Every bug fix gets a regression test, and a mutation runner deletes the fix from a throwaway copy of the code to confirm the test actually fails without it - 1,455 of those on file today.
  • Speed measured, not assumed. With 5,000 notes the app starts in about two seconds and saves a note in about 42ms - benchmarked, with the pre-optimization numbers kept on record for comparison.
  • Cross-platform by share code, not by account. A note, or a full backup, moves between the Windows app and the Android companion as a plain share code - no server, no account, no sync service sitting in between - and it's the desktop app's own code that reads an Android export back in, not a format the two just happen to agree on.

How it was built

Python 3.13 and Tkinter, with exactly one runtime dependency (Pillow, for image previews) - plain local JSON files for storage, no database. The code is split into a core/ data layer that is never allowed to import Tkinter, and a set of UI mixins built on top of it; every dropdown and dialog is hand-built rather than relying on the OS's own, except for the five places (opening a file, saving an export) where the OS picker is genuinely better. The project's own working agreement with its AI coding agent - what runs without asking, what always needs a human decision, and why - is public on the project site, along with the test plan and the numbers behind the Quality block above.

The Android companion is a separate app, written in Kotlin, with its own repository and its own test suite - kept interoperable with the desktop app only through a shared share-code and backup format, never through a server. Its source is public at noteOrganizerForAndroid, and there's a dedicated Android demo you can try in the browser, right alongside the desktop one.
