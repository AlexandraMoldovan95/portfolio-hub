Desktop Buddy

A Windows app that records only the app you are testing, starts and stops by itself, and turns the run into short MP4 clips. I built it to film AI-agent test runs of my own apps, and I tested it like a QA project: 72 written test cases, all passed, and a log of 27 bugs with steps to reproduce. Try the playable demo in your browser.

What it does

An animated buddy that grows with your focus time. It records one app window by its title, joins relaunches into one file, lets you mark good moments with one click, and cuts clips or a short movie from them. Also a focus timer with statistics, notes with reminders, a clipboard history that never saves secrets, and screenshots you can draw on. Works offline.

My role

Product idea, UX and visual design, feature specs, the test plan and the bug log, and three audit rounds. The code was written in pair-programming with an AI assistant (Claude).

Proof

72 of 72 written test cases passed · 27 bugs logged · 295 unit tests, run on Windows on every push.

How I tested it

A desktop app that records other windows, saves your notes and touches files can lose data in ways a quick click-through never shows. So I wrote the test cases down, ran them, and logged every bug with steps to reproduce it.

Three layers of checks

The 72 test cases are in a workbook in standard QA format: preconditions, steps, expected and actual result, priority, type. They were written and run on 4 and 5 October 2026.

Bugs I logged, and how each was found

The log has 27 bugs. 20 came from audit rounds, where AI reviewers examined the app for data loss, security, speed on a weak PC and beginner confusion, and I turned each finding into a reproducible bug. The other 7 came from my own use on Windows. Most fixes came with a test. Three examples:

  • Data loss (BUG-002). Found by an audit. When antivirus or OneDrive locked the notes file, the app treated it as empty and overwrote it when you quit: 1 note before, 0 after. The app now never overwrites a file it couldn't read.
  • The heart eyes disappeared (BUG-020). Found by me after a release. Choosing "Hearts" for the eyes showed only white dots. A new petting heart used the same style name as the eyes and hid them. I renamed it and added a test that fails if the page ever restyles anything the face is drawn with.
  • A shortcut that didn't work (BUG-021). Found by me while taking screenshots: Ctrl+Shift+F9 marked nothing on my laptop, and a shortcut that works everywhere can steal keys from the app being tested. My decision was to remove it. A small flag next to the buddy now marks the moment with one click.

Three audit rounds

Round 1 found about 100 issues and round 2 about 40. Round 3, a confirmation round, found 7 low-severity issues and nothing critical, high or medium. The cheap ones were fixed in 1.16.1.

How it's built

Electron (a toolkit for building desktop apps from web technology) with plain JavaScript: no UI framework, no build step.

  • Easy to test. The decision-making logic lives in small modules that don't need the app window, so the 295 unit tests run in seconds.
  • No video program bundled. Clips are cut by replaying the video and recording it again with the browser's own tools. It takes as long as the clip, but the installer stays small.
  • Private by default. The only network use is sending an email you ask for. A test fails if any other part of the code touches the network, and saved passwords are encrypted with your Windows account.
  • A demo from the same code. The live demo runs the app's real pages in the browser, with a stand-in for the parts only a desktop app has. A test fails if the demo falls out of step with the app.

What I haven't done yet

  • The audits were done by AI reviewers and me, not by independent testers.
  • The manual test cases were last run on 4 and 5 October 2026, before 1.16.2. That release updated two libraries for security alerts and gave the picture window a light theme.
  • It is Windows only in practice. The macOS code has never been tested, and the installer isn't code-signed, so Windows SmartScreen warns once.
  • No sound in recordings, because Windows doesn't expose sound per window.
